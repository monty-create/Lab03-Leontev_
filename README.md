# Практическая работа №3. Операторы и выражения

## Цель работы
Изучить работу составных операторов присваивания, исследовать разницу между постфиксным и префиксным инкрементом, освоить операторы сравнения и логические операторы C#, а также понять механизм «короткого замыкания» при вычислении выражений.

## ПР3. Ответы на контрольные вопросы

### 1. Чем x += 5; отличается от x = x + 5;? Есть ли разница в результате?
С точки зрения конечного математического результата разницы нет — в обоих случаях значение переменной увеличится на 5. Разница заключается в форме записи: `x += 5;` — это сокращенный (составной) оператор присваивания. Он записывается компактнее, избавляет от необходимости дублировать имя переменной в правой части и делает код более читаемым, особенно при работе со сложными структурами.

### 2. В чём разница между x++ и ++x, если результат сразу используется в выражении (например, передаётся в Console.WriteLine)?
Разница заключается в порядке выполнения операции инкремента:
- **Постфиксный инкремент (x++)** сначала возвращает в выражение текущее (старое) значение переменной, и только после этого увеличивает саму переменную на 1. В ходе эксперимента это наглядно видно на примере `score1++ * 3`, где берется старое значение 10, а также в `saved = score3++`, где в переменную `saved` записывается исходная десятка.
- **Префиксный инкремент (++x)** сначала увеличивает значение переменной на 1, а затем возвращает в выражение уже обновленный результат. На примере `sumPre = ++score2 + 5` видно, что переменная сначала выросла до 11, и результат стал равен 16.

### 3. Какой тип данных всегда получается в результате оператора сравнения (==, !=, <, >= и т.д.)?
Результатом работы любого оператора сравнения всегда является логический тип данных — **bool**. Переменные этого типа могут хранить только два значения: `true` (истина, если проверяемое условие выполняется) или `false` (ложь, если условие неверно).

### 4. Что такое «короткое замыкание» в && и ||? Приведите свой пример, когда это имеет практическое значение.
Короткое замыкание (short-circuit evaluation) — это оптимизация вычислений логических выражений в .NET. Если результат всего выражения становится понятен уже по первому операнду, среда выполнения даже не начинает вычислять второй:
- В операторе `&&` (И), если первый операнд равен `false`, то все выражение гарантированно примет значение `false` — второй операнд пропускается.
- В операторе `||` (ИЛИ), если первый операнд равен `true`, то все выражение железно будет `true` — второй операнд игнорируется.
В ходе работы метод `CheckAndPrint` наглядно доказал это: при проверке `&&` строка "Вычисляется: B" даже не появилась в консоли, так как первый операнд "A" изначально вернул `false`.

### 5. Расставьте приоритет для выражения 10 - 2 * 3 + 4 / 2, посчитайте вручную, а затем проверьте кодом.
Согласно правилам приоритетов в C#, первыми выполняются операции умножения и деления (слева направо), а затем операции вычитания и сложения (слева направо):
1. Умножение: `2 * 3 = 6`. Выражение принимает вид: `10 - 6 + 4 / 2`.
2. Деление: `4 / 2 = 2`. Выражение принимает вид: `10 - 6 + 2`.
3. Вычитание: `10 - 6 = 4`. Выражение принимает вид: `4 + 2`.
4. Сложение: `4 + 2 = 6`.
Результат ручного расчета полностью совпадает с арифметической логикой языка C# и равен **6**.

### 6. Почему хорошим тоном считается расставлять скобки даже там, где они не обязательны по приоритету операций?
Это значительно повышает читаемость исходного кода для человека (как для самого разработчика спустя время, так и для преподавателя на проверке). Когда скобки расставлены явно (например, в сложных логических цепочках вроде `(5 > 3 && 2 < 4) || false`), логика считывается мгновенно, и человеку не приходится мысленно вычислять приоритеты операторов. Также это страхует от случайных логических ошибок при изменении кода в будущем.
